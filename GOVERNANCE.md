# Governance

Team Spaces is developed in public under the Apache License 2.0. Project
decisions should be visible, reviewable, and guided by user value, security,
maintainability, portability, and cost-conscious operation.

## Roles

- **Contributors** report issues, propose designs, improve documentation, and
  submit changes.
- **Maintainers** review and merge changes, manage releases, moderate project
  spaces, and steward security and architectural boundaries.

Consistent, constructive participation is the normal path to maintainer
responsibility. Maintainer access is granted or removed by consensus of the
current maintainers. Repository access does not grant ownership of a
contributor's work or change its license.

## Decisions

Routine decisions are made in issues and pull requests. Maintainers seek rough
consensus, considering technical evidence and affected users rather than vote
counts alone. If consensus cannot be reached, a maintainer who is not conflicted
may make and document the narrowest reversible decision.

Changes to architecture, compatibility, security boundaries, data formats,
governance, or licensing require public rationale and appropriate review.
Durable architectural decisions belong in an ADR. Security-sensitive details
may remain private until coordinated disclosure is safe.

## Releases and project policy

Releases come from reviewed commits on `main` and use semantic versioning once
tagged releases begin. A maintainer must not approve their own material change
without another review when another maintainer is available.

Governance and community-policy changes use the same pull-request process as
code. Conduct enforcement and vulnerability response follow their dedicated
policies.
